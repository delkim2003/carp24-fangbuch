## DATEIEN (ALLE NEU ANLEGEN)

### 1. web/src/lib/admin.ts — Guard-Helfer
```ts
import { createServerClient } from "@supabase/ssr";
import type { AstroGlobal } from "astro";

export async function getSessionAndProfile(Astro: AstroGlobal) {
  const supabase = createServerClient(import.meta.env.PUBLIC_SUPABASE_URL, import.meta.env.PUBLIC_SUPABASE_ANON_KEY, { cookies: { getAll() { const h = Astro.request.headers.get("cookie"); if (!h) return []; return h.split(";").map(p => { const i = p.indexOf("="); if (i === -1) return null; return { name: p.slice(0, i).trim(), value: p.slice(i + 1).trim() }; }).filter(Boolean) as { name: string; value: string }[]; }, setAll(cs) { cs.forEach(({ name, value, options }) => { Astro.cookies.set(name, value, options); }); } } });
  const { data: { session } } = await supabase.auth.getSession();
  if (!session) return { supabase, session: null, profile: null, isAdmin: false };
  const { data: profile } = await supabase.from("profiles").select("id, display_name, role, is_pro").eq("id", session.user.id).single();
  const role = profile?.role ?? "USER";
  return { supabase, session, profile, isAdmin: role === "ADMIN" || role === "MODERATOR" };
}
```

### 6. API-Routen (ALLE mit identischem Admin-Guard-Pattern)
Für JEDE Route: SSR-Client bauen (gleiches Cookie-Muster), session prüfen (401), profiles.role prüfen (403), DANN supabaseAdmin für alle Datenzugriffe.

#### /api/admin/stats.ts — GET
Counts via supabaseAdmin: profiles (eq deleted_at null), catches (eq deleted_at null), content_reports (eq status open), forum_threads, forum_posts, chat_messages, marketplace_items, trips. → { stats: {...} }

#### /api/admin/reports.ts
- GET?status=open|resolved: content_reports (order created_at desc, limit 100) + reporter profile (display_name via join profiles!reporter) + Ziel-Vorschau je target_type (extra Queries: catches/forum_threads/forum_posts/chat_messages/marketplace_items)
- PATCH {id}: set status='resolved', resolved_at=now(), resolved_by=session.user.id
- DELETE {id} (+ optional target_id/target_type im Body): Inhalt löschen (catch → UPDATE catches SET deleted_at=now() WHERE id; forum_thread → DELETE forum_threads; forum_post → DELETE forum_posts; chat_message → DELETE chat_messages; marketplace_item → DELETE marketplace_items) UND Report: status='resolved', resolved_at=now(), resolved_by=session.user.id

#### /api/admin/users.ts
- GET: supabaseAdmin.auth.admin.listUsers() → users (email) + profiles (role, is_pro, display_name, created_at, deleted_at) + counts (catches per user, limit 200)
- PATCH {id, role?, is_pro?}: UPDATE profiles SET role/is_pro WHERE id (nur wenn Ziel nicht der letzte ADMIN — einfach halten: erlauben)
- DELETE {id}: UPDATE profiles SET deleted_at=now() WHERE id (soft delete; KEIN hard delete — auth.users bleibt)

#### /api/admin/content.ts
- GET?type=catch|forum|chat|marketplace&q=: Listen (limit 50, order created_at desc, mit display_name-Join via profiles-FK; q filtert ILIKE auf species/body/title/display_name)
- DELETE {type, id}: catch → soft delete (deleted_at=now()); forum/chat/marketplace → hard DELETE

#### /api/admin/me.ts — GET
Session + role → { isAdmin: boolean, role: string } (für Header-Link client-seitig)
