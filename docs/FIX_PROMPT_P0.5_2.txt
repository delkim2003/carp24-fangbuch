Fix 2 verifizierte P0.5-Funde in carp24 (Backup-System).

============================================================
FIX 1 (🟠 DoD-Bruch): .env + Config-Dateien in backup.sh mit aufnehmen
PROBLEM: backup.sh sichert nur pg_dump + Storage. Die Backup-Passphrase (BACKUP_PASSPHRASE) liegt NUR in infra/.env — bei Totalverlust der Platte ist sie weg → Backup unentschluesselbar. Auch kong.yml + docker-compose.yml fehlen (essentiell fuer Voll-Recovery).
FIX: In infra/backup.sh NACH dem Storage-Tar (vor Rotation) einen Config-Tar ergaenzen:
  if [ -f "$SCRIPT_DIR/.env" ] || [ -f "$SCRIPT_DIR/docker-compose.yml" ] || [ -d "$SCRIPT_DIR/volumes/api" ]; then
    tar -czf "$BACKUP_DIR/config_$DATE.tar.gz" \
      -C "$SCRIPT_DIR" .env docker-compose.yml \
      -C "$SCRIPT_DIR/volumes/api" kong.yml 2>> "$LOG" \
      && echo "[$DATE] Config-Tar OK" >> "$LOG" \
      || echo "[$DATE] FEHLER: Config-Tar" >> "$LOG"
  fi
Dann diesen Tar GENAU WIE die anderen verschluesseln:
  gpg --batch --yes --symmetric --cipher-algo AES256 --passphrase "$BACKUP_PASSPHRASE" \
    -o "$BACKUP_DIR/config_$DATE.tar.gz.gpg" "$BACKUP_DIR/config_$DATE.tar.gz"
  rm -f "$BACKUP_DIR/config_$DATE.tar.gz"
In die Offsite-Kopie aufnehmen (config_$DATE.tar.gz.gpg mitkopieren).
In die Rotation aufnehmen (config_*.tar.gz.gpg wie die anderen, max 7).

============================================================
FIX 2 (🟠 DoD-Bruch): Kein Cron fuer taeglichen Backup
PROBLEM: BAUPLAN verlangt 'taeglich', aber es gibt keinen Cron fuer carp24-backup.sh.
FIX: Cron als Hermes-Cronjob anlegen (täglich 02:30 Uhr, nach dem System-Backup 02:00):
  NAME: carp24-backup-daily
  SCHEDULE: 0 2 30 * * *  (bzw. '30 2 * * *' Cron-Syntax)
  PROMPT: Führe /mnt/projekte/carp24-fangbuch/infra/backup.sh aus. Prüfe danach: (1) exit code 0, (2) neueste .gpg-Datei existiert in infra/backups/, (3) Offsite-Kopie in /mnt/projekte/vault/02_SYSTEM/BACKUPS/carp24/ existiert und gleiche Größe. Melde Ergebnis kompakt (1-3 Zeilen). Bei Fehler: klare Fehlermeldung.
  DELIVER: origin (Telegram)
  SCRIPT: /mnt/projekte/carp24-fangbuch/infra/backup.sh (als no_agent Script-Job ODER via Prompt — wähle die robustere Variante: no_agent=True mit backup.sh als Script, damit kein LLM noetig ist; stdout wird geliefert)
HINWEIS: Falls die Cron-Erstellung nicht via Agent-Tool geht, nutze: hermes cron add --name carp24-backup-daily --schedule "30 2 * * *" --script /mnt/projekte/carp24-fangbuch/infra/backup.sh --no-agent --deliver telegram:Home
