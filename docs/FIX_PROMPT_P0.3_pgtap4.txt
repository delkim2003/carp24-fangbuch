Fix 3 Punkte in tests/pgtap/0001_rls_tests.sql (Postgres 17, pgTAP).

ROOT CAUSE der 2 Test-Fehler (verifiziert in psql):
T9 und T12 nutzen eine Subquery, um die fremde catch-ID zu holen:
  (SELECT id FROM public.catches WHERE user_id = 'bbbbbbbb-...' LIMIT 1)
Diese Subquery läuft als User A (authenticated, jwt=aaaaaaaa) → RLS blockt SELECT auf fremde Zeilen → Subquery liefert NULL → publish_catch(NULL) wirft 'catch not found' statt 'not your catch'.
Der RPC-Code selbst ist KORREKT (RAISE EXCEPTION 'not your catch' bei fremder catch).

FIX: Feste UUIDs. Beim Seed der fremden catch im INSERT die id-Spalte explizit setzen, dann im throws_ok die feste UUID direkt übergeben (keine Subquery).

STELLE 1 — Test T9 (Zeile ~283-315): "publish_catch fremde catch → EXCEPTION"

Aktuell:

  (user_id, water_id, catch_ts, species, weight_kg, draft, client_uuid)
VALUES (
  'bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb',
  'e0e0e0e0-e0e0-e0e0-e0e0-e0e0e0e0e0e0',
  now(), 'SPIEGEL', 8.0, true,
  '55555555-5555-5555-5555-555555555555'

...
SELECT throws_ok(
  $$SELECT public.publish_catch(
    (SELECT id FROM public.catches
