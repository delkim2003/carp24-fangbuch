## Feature: DSGVO-Datenexport (Art. 20) — Task 1.5.1a, Pflicht VOR Beta-Usern

### 2) Client-Script (im bestehenden `<script is:inline>` von profil.astro ergänzen — nutzt das vorhandene getSupabase()-Muster!):
- Lade `getSupabase()` wie die bestehenden Funktionen (window.supabase.createClient aus body.dataset).
- `async function fetchAllMyData()`: 
  - `supabase.auth.getUser()` → Profil-Infos (id, email, created_at, user_metadata)
  - `supabase.from("profiles").select("*").single()` → display_name, bio, home_water, avatar_url
  - `supabase.from("catches").select("*").order("catch_ts", { ascending: false })` → ALLE eigenen Fänge (RLS liefert nur eigene; inkl. draft-Fänge — das sind auch personenbezogene Daten!)
  - Rückgabe: { exported_at: ISO, user: {...}, profile: {...}, catches: [...] }
- `function downloadBlob(filename, content, mime)`: Blob + URL.createObjectURL + a[download]-Klick + URL.revokeObjectURL.
- JSON-Export: JSON.stringify(data, null, 2), MIME "application/json", Dateiname `carp24-datenexport-YYYY-MM-DD.json`
- CSV-Export: Kopfzeile `Datum;Gewicht_kg;Fischart;Gewaesser;Laenge_cm;Koeder;Methode;Notizen;Lat;Lng;Wetter;Foto_URLs` — Fänge als Zeilen, Felder mit Semikolon getrennt, Text in Anführungszeichen, escape doppelte Quotes. Keine Koordinaten-Rundung (eigene Daten = exakt). Datum in Europe/Vienna-Format (DD.MM.YYYY HH:mm). MIME "text/csv;charset=utf-8", Dateiname `carp24-faenge-YYYY-MM-DD.csv` (CSV = nur Fänge; Profil-Daten nur im JSON).
- Buttons: click-Handler mit Status-Meldung ("Export wird erstellt…" / "✓ Export bereit — Download gestartet" / Fehler).
- Fehlerbehandlung: showExportStatus(msg) mit Sichtbarkeit.
