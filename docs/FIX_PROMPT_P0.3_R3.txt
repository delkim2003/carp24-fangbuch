FIX 1 (🟠 Moderations-Bypass via DELETE+Re-create): posts_delete_owner status-Clamp
PROBLEM: posts_delete_owner hat NUR USING (user_id = auth.uid()) OHNE status-Bedingung. Ein Moderator setzt einen Post auf HIDDEN → der Owner kann ihn per DELETE löschen (kein status-Filter) → via create_post() einen NEUEN Post mit demselben catch_id erstellen (kein UNIQUE-Constraint auf posts.catch_id) → neuer Post ist VISIBLE. Moderation wird komplett umgangen.
AKTUELL (Z.~452-455):
  CREATE POLICY posts_delete_owner ON public.posts
    FOR DELETE TO authenticated
    USING (user_id = auth.uid());
FIX:
  CREATE POLICY posts_delete_owner ON public.posts
    FOR DELETE TO authenticated
    USING (user_id = auth.uid() AND status = 'VISIBLE');
(Owner kann nur noch VISIBLE Posts löschen — HIDDEN-Posts (moderiert) sind für ihn unsichtbar/löschbar. Konsistent mit posts_update_owner und forum-Policies.)
