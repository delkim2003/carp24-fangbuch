## GAP B1: MARKTPLATZ KONTAKT-FORMULAR (Plan E4: „Kontakt über internes Formular")

### Migration 0029_marketplace_contacts.sql (NEU unter supabase/migrations/)
```sql
CREATE TABLE IF NOT EXISTS public.marketplace_contacts (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  item_id uuid NOT NULL REFERENCES public.marketplace_items(id) ON DELETE CASCADE,
  from_user uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  to_user uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  message text NOT NULL CHECK (char_length(message) BETWEEN 3 AND 2000),
  created_at timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE public.marketplace_contacts ENABLE ROW LEVEL SECURITY;
CREATE POLICY marketplace_contacts_insert_own ON public.marketplace_contacts
  FOR INSERT TO authenticated WITH CHECK (from_user = auth.uid());
CREATE POLICY marketplace_contacts_select_participant ON public.marketplace_contacts
  FOR SELECT TO authenticated USING (from_user = auth.uid() OR to_user = auth.uid());
```

## GAP B2: PUSH-TRIGGER (Plan E2: Community-Antwort + Fang-Erinnerung)

### API web/src/pages/api/push/notify.ts (NEU)
- POST, prerender = false; SSR-Auth (401 ohne Session)
- Body: { type: "forum_reply", thread_id?: string }
- Nur type forum_reply implementieren:
  1. thread_id validieren → forum_threads select user_id where id → 404 wenn fehlt
  2. push_subscriptions des Thread-Owners laden (select endpoint, keys where user_id = owner AND owner != session.user.id)
  3. web-push senden (import webpush von "web-push"; VAPID aus import.meta.env.VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY / VAPID_SUBJECT — falls fehlen → 503 {error: "Push ist noch nicht konfiguriert."})
  4. payload: { title: "Neue Antwort", body: "Jemand hat auf deinen Thread geantwortet.", url: "/forum/{thread_id}" } — pro Subscription send (try/catch je Subscription; 410 → Subscription löschen)
  5. Antwort: {sent: n} 200

- Nach ERFOLGREICHEM Antwort-Insert (im then-Block des Antworten-Submits): fire-and-forget fetch('/api/push/notify', {method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({type:'forum_reply', thread_id: THREAD_ID})}) — THREAD_ID ist im Astro-define-vars verfügbar (prüfe vorhandene Variablen; falls threadId nicht existiert, im define-vars ergänzen).
